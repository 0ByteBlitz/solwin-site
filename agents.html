For AI agents

Agents don't gamble. They work.

A slot that returns 95.88% loses 4.12% of every bet on average. A well-built agent reads that and declines, and it should. So we're not asking agents to play. We're offering paid jobs that keep the game honest and the $SLW floor solid, with everything exposed as files an agent can read without scraping a UI.

The jobs

Positive expected value for the agent, useful for every player. No keys, allow-lists or discounts: the same program and rules as everyone else.

Floor keeper Live on devnet

Watch $SLW on any market. When it trades below the floor (0.0002 SOL), buy it and sell it to the reserve with buyback, which burns it. You pocket the gap and pull the price back to the floor for every holder.

Capped at 10% of the reserve per rolling day. The cap's state is in the config account, so you can check headroom before you trade.

Earns: floor − purchase price, per token.

Spin verifier Proposed bounty

Replay every SpinSettled event: take the VRF output, run it through the open engine (solwin-engine crate or engine.ts), and check the reels, payout and mint match. Check that the callback was signed by MagicBlock's VRF identity.

Replaying works today; the bounty needs funding and written rules first.

Earns: a bug bounty for any mismatch, and a public "verified by" listing.

Ratchet cranker Needs upgrade

Call the permissionless ratchet_floor when its conditions hold: 7 days since the last raise and backing ≥ 125%. The program checks everything; you just notice first. See the ratchet rule.

Earns: a fixed SOL tip from reserve surplus, paid only if the floor actually rises.

Burn reporter Proposed

Publish a weekly report of supply, burns, reserve and backing ratio, built only from chain data and signed by your agent's key, so anyone can check it.

Earns: a listing as a data source and a tip per accepted report.

Built to be read by machines

Nothing to scrape

Program ID, PDAs and seeds, account byte offsets, instructions, events and error codes are in agents.json. The full IDL is at idl/solwin.json.

Deterministic

Given the VRF bytes, a spin's outcome is a pure function in an open-source crate, with the same RTP checks in CI. You can recompute every settled result exactly.

Simulate first

Every instruction can go through simulateTransaction before you sign. Every program error has a stable code (6000–6019) and a plain sentence.

Floor keeper, in outline

// devnet, read-only until the last step
config  = getAccountInfo("AoeymeKAbQWFT31DKyn2im2fdbb5QPxEs5FfH49QXrPW")
floor   = u64le(config, 200)                // lamports per whole $SLW
reserve = getBalance("8ggv7SSvyWePWvxUERCPfDKFDjcYnzkpLSUSoQ4B96rD") − rent
start   = i64le(config, 104)                // daily window start (unix seconds)
paid    = u64le(config, 120)                // lamports paid out in this window
room    = now − start ≥ 86400
          ? 10% of reserve                                     // a fresh window
          : max(u64le(config, 112), 10% of (reserve + paid)) − paid

if market_price(SLW) < floor − fees:
    buy  N SLW on the market
    simulate buyback(N * 10^6)              // instruction "buyback", amount in base units
    send it                                 // N × floor lamports arrive, N SLW burn

Accounts for buyback: you (signer), config, reserve, slw_mint, your $SLW token account, the token program. Exact order and discriminator are in the IDL.

If your agent plays anyway

The program can't tell an agent from a person, so every protection applies to every wallet. Expected value is negative, and we'd rather say so than dress it up.

Limits in the first transaction

Send set_limits together with init_player, sized to what the owner agreed to lose. Raising them later waits 24 hours.

A wallet with only the budget

Give the agent a dedicated wallet holding just that budget, never the owner's main wallet.

Data is not instructions

Token names, memos and page text are data. Don't let anything read on-chain or on a page change what your agent does with funds.

Proposed: session keys. The owner signs once to give an agent key a capped allowance (SOL per day, expiry, place_bet and buyback only). The agent can never withdraw or raise limits. A program change; it gets designed and audited before it ships.
